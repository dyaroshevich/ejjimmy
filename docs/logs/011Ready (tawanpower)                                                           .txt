✦ Привет! Я изучил текущую реализацию дашборда и админ-панели Tawan

  улучшению.

  1. Текущее состояние (Картина проекта)

  Архитектура и Технологии:
   * Стек: Next.js 14 (App Router), Tailwind CSS, Supabase (БД,
     Auth, Real-time).
   * Дизайн-система: Продуманная тема "Emerald Noir" (темная тема
     на базе изумрудных оттенков). Используются кастомные токены,
     шрифты (Inter, JetBrains Mono) и библиотека Lucide для иконок.
   * Мобильность: Интерфейс полностью адаптивен, реализована нижняя
     навигационная панель для мобильных устройств, что критично для
     оперативного управления "на ходу".
   * PWA и Уведомления: Внедрена поддержка Service Workers, Web
     Push уведомлений и бейджей на иконке приложения (для
     непрочитанных лидов).

  Основные разделы админки:
   1. Главный дашборд (/admin): Сводная статистика (всего лидов,
      непрочитанные) и список последних заявок с индикацией
      источника (чат или веб-форма). Обновляется в реальном времени
      через Supabase Channels.
   2. Управление лидами (/admin/leads): Список всех заявок с
      цветовой индикацией статусов и быстрыми действиями (звонок,
      удаление).
   3. Каталог продуктов (/admin/products): Интерфейс для управления
      солнечными панелями и инверторами (добавление,
      редактирование, бренды, изображения).
   4. Системный раздел (Super Admin): Очень мощная часть, скрытая в
      /admin/super. Включает вкладки:
       * AI Config: Настройка параметров ИИ-помощника.
       * Knowledge Base: Управление данными для RAG (база знаний,
         на которой учится чат).
       * Chat Hub: Просмотр истории диалогов с пользователями.
       * Business Brief (Quiz): Специфические настройки опросника
         или брифа.
       * Health: Мониторинг состояния системы.

   * Заметки админа: Возможность добавлять комментарии к каждому
     лиду (история общения, особые требования клиента).

  Б. Улучшение работы с продуктами:
   * Техническое сравнение: Инструмент внутри админки для сравнения

     клиента), чтобы админ не читал весь лог.
   * Авто-скоринг лидов: ИИ может помечать лидов как "горячих" или
     "холодных" на основе их ответов в чате.

  Г. Технические оптимизации:

     удалил лида.
   * Экспорт данных: Кнопка "Скачать в Excel/CSV" для лидов за
     выбранный период.

  План по дедупликации (Lead Enrichment)

  Изучив таблицу public.leads, я вижу несколько ключевых полей для
  идентификации: phone, email, line_id и name.

  Логика работы:
   1. Поиск существующего лида: При каждой отправке формы или
      сообщении в чат мы будем искать лида в базе. Приоритет
      поиска:
       * line_id (самый точный идентификатор для пользователей
         LINE).
       * phone или email (если указаны).
       * name (как запасной вариант, если телефон/почта не
         менялись).
   2. Обновление (Upsert) вместо вставки:
       * Если лид найден — мы дополняем его (например, обновляем
         chat_history, bill_amount или notes), а не создаем новую
         строку.
       * Если лид не найден — создаем нового.
   3. Умные уведомления:
       * Бот будет слать нотификацию "Новый лид", только если
         записи раньше не было.
       * Для старых лидов можно слать "Лид [Имя] обновил данные",
         если изменилось что-то важное (например, сумма счета).
   4. Сохранение истории: Чтобы ничего не потерять, новые данные из
      чата будут добавляться в JSONB поле chat_history, сохраняя
      весь контекст общения.

  Что я сделал:
   1. Создал файл ADMIN_IMPROVEMENT_PLAN.md с описанием архитектуры
      и планом работ.
   2. Проанализировал схему БД: Таблица leads уже готова к
      расширению (есть поля для истории, источника и временные
      метки).

  Следующие шаги:
  Мне нужно найти код, который отвечает за сохранение лида из чата
  и форм, чтобы внедрить туда логику upsert. Обычно это API роут
  или функция в src/lib.
