# 🛡️ План интеграции Vercel KV (Redis) и Supabase RAG

Этот документ описывает архитектуру защиты, ускорения и расширения функционала Chat API для проекта Solar Energy Krabi.

## 🏗️ Архитектура системы
Система строится на принципе "эшелонированной обороны":

1.  **Layer 1: Vercel KV (Rate Limiter)** — блокирует спам и ботов по IP.
2.  **Layer 2: Vercel KV (Cache)** — отдает мгновенные ответы на частые вопросы.
3.  **Layer 3: Supabase (Knowledge Base)** — выполняет поиск технической информации (pgvector RAG).
4.  **Layer 4: Gemini 2.5 Flash (AI)** — генерирует финальный ответ.

## 🔄 Жизненный цикл запроса (Request Flow)
1.  **IP Check**: Проверка лимита (макс. 5-10 сообщений в минуту).
2.  **Cache Hit?**: Поиск точного совпадения вопроса в Redis. Если найдено — возврат ответа (0.01s).
3.  **RAG Search**: Поиск в Supabase по таблицам `solar_products` и `knowledge`.
4.  **AI Generation**: Отправка контекста из Supabase в Gemini.
5.  **Cache Update**: Сохранение ответа в Redis с TTL (временем жизни) например 24 часа.

## 🚀 Расширенный функционал Redis (Будущее)
Помимо защиты, Redis позволит реализовать следующие "Elite" фишки:

1.  **Social Proof (Live Activity)**: Отображение счетчика активных пользователей или последних расчетов в реальном времени.
2.  **Wizard Recovery**: Сохранение промежуточного состояния калькулятора, чтобы пользователь мог продолжить заполнение после закрытия вкладки.
3.  **Kill Switch**: Глобальный лимит затрат на API в день. При достижении порога чат автоматически отключается для защиты бюджета.
4.  **Admin Live View**: Отображение статуса "Печатает..." или "Просматривает товар" в админ-панели для оперативного вмешательства менеджера.
5.  **Персонализация**: Краткосрочное хранение контекста пользователя без необходимости регистрации.
